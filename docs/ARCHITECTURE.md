# Архитектура

## Общая схема

WIRES — статическое приложение без backend и серверного состояния. Браузер загружает `index.html` и три ES-модуля. `npm run build` копирует только эти четыре public assets в `dist/` для публикации.

```text
index.html
├── разметка и CSS
├── UI и interactions
└── physics loop

src/model.js
├── constants и model limits
├── normalizeModel
└── pin/grid helpers

src/wires-format.js
├── parseWires
└── serializeWires

src/collision.js
├── pin spatial index
├── segment query
└── collision response
```

Unit-тесты используют `node:test`. Browser suite управляет Chromium через CDP без сторонних npm-зависимостей.

## Модель данных

```js
{
  version: 1,
  cell: 44,
  background: '#102cff',
  pointMode: 'white',
  gridVisible: true,
  wires: [
    {
      id: '0001',
      x: 7,
      y: 2,
      length: 10,
      color: '#102cff',
      endX: 20,
      endY: 7
    }
  ]
}
```

`pointMode` принимает `white`, `wire` или `background`. Legacy-поле `pointsMatchBackground` мигрирует во время нормализации. `endX` и `endY` присутствуют у закреплённого хвоста.

Модель ограничена 1000 жгутами. Parser отклоняет превышение. `normalizeModel` ограничивает внешние данные, а Add, Duplicate, Brush и Alt-copy проверяют ёмкость до изменения state.

## Runtime-физика

Каждый жгут получает runtime-массив внутренних точек. Старт и закреплённый хвост выступают ограничениями. Verlet-подобный шаг использует гравитацию, сопротивление воздуха (оба — ползунки в меню «поведение») и десять проходов коррекции расстояния. Физика идёт с фиксированным шагом 60 Гц через аккумулятор, поэтому поведение не зависит от частоты дисплея.

После связей работает натяжение от концов (`tetherRope()`): точка не может уйти от закреплённого конца дальше, чем длина шнура между ними, с запасом 0.4% в сторону натяга. Так длинная цепочка не провисает от собственной мягкости, и сматывание даёт прямую. Мерка по прямой верна только до первого пина, которого жгут касается: за пином путь вдоль жгута длиннее прямой, и натяжение потащило бы жгут сквозь пины. Поэтому от старта оно действует до первого контакта, от хвоста — до последнего.

Формы жгутов сохраняются в `localStorage['wires-shapes']` (при уходе со страницы и через две секунды после изменения) и восстанавливаются при загрузке, если у жгута те же старт, хвост, длина и размер клетки. Иначе форма строится заново — и тогда это только догадка, которая может лечь сквозь пины.

Закреплённый жгут со слабиной начинается с параболической заготовки: прямая линия между двумя пинами — неустойчивое равновесие, боковой силы нет, и жгут остаётся натянутым сколь угодно долго вместо провисания. Стрела прогиба берётся как `sqrt(3·пролёт·слабина/8)`, снизу ограничена половиной слабины, сверху половиной длины.

После drag запускается release-фаза на 90 кадров. Idle-жгут не пересчитывает готовый SVG path без движения. При `prefers-reduced-motion: reduce` runtime использует прямую интерполяцию.

## Spatial collision index

`buildPinSpatialIndex()` строит hash пинов, когда коллизии включены. Индекс кешируется и пересобирается только после изменения модели — `syncScene()` сбрасывает кеш — либо при смене размера клетки. Сегмент запрашивает buckets вокруг своего bounding box, расширенного на clearance. Кандидаты сортируются по исходному порядку пинов, поэтому contact response детерминирован.

`collectSegmentCandidates()` собирает кандидатов один раз на шаг физики (с запасом clearance + клетка), и все проходы solver'а работают по одному списку.

### Контакт с памятью стороны

Зазор между центром пина и осью жгута — ровно одна клетка: радиус пина плюс половина толщины жгута. Тогда жгут проходит между пинами через клетку впритык, а соседние (по стороне или диагонали) пины он не проходит — между ними меньше толщины жгута. Такие пины `pinClusters()` собирает в одно препятствие.

Раньше каждый пин толкал отрезок отдельно и частично (`correction`, `maxPush`, `slop`). У касающихся пинов зоны запрета перекрываются, и в их «перешейке» толчки направлены навстречу друг другу: отрезок застревал внутри, дрожал, а под натяжением проскакивал насквозь. Новый solver (`prepareRopeContacts()`, `resolveRopeContacts()`, `settleRopeContacts()`) устроен иначе:

- **Сторона.** Для каждой пары «отрезок — пин» известно, слева пин или справа. Отрезок выталкивается только на эту сторону и до полного зазора; пересечение — это просто отрицательный зазор, его чинит тот же толчок.
- **Откуда сторона.** Из начала кадра, если пин там явно по одну сторону (дальше половины зазора от оси). Кадр кончается разрешёнными контактами, поэтому это надёжно. Глубокому контакту сторона берётся из памяти прошлого кадра (с соседних отрезков — пин едет вдоль жгута). Впервые увиденный глубокий пин вместе со всем кластером идёт туда, где уже лежит бо́льшая часть жгута.
- **Призраки.** Новый жгут строит форму наугад (парабола, отвес) и может лечь глубоко в пины. Такие пины он не трогает, пока из них не выйдет, — иначе противоречивые стороны растягивали бы его в разы.
- **Конец в пине.** Закреплённый конец можно завести в пин: при перетаскивании рука неточна, а проход между пинами ровно в толщину жгута. Жгут не может держаться от этого пина дальше, чем сам конец, поэтому зазор до пина сжимается до расстояния от конца — плавно, вместе с концом. Раньше такой пин выключался целиком, и дрожь руки у края пина давала рывки и жгут, лежащий сквозь точки.
- **Препятствия считаются по жгуту.** Кластеры собираются из пинов рядом с жгутом, без его собственных: иначе его же старт склеивал бы соседние пины в одно препятствие.
- **Скорость.** Контакт неупругий: нормальная скорость гасится, касательная теряет 30% на трение. Поправка для пина, в котором жгут был уже в начале кадра, считается исправлением положения, а не ударом, и скорости не добавляет.
- **Страховка.** Один толчок сдвигает точку не больше чем на полклетки, чтобы неразрешимое противоречие не взорвало жгут.

Прогон на полигоне сцен с близкими пинами (падение на пару, блок 2×2, гребёнку, сетку через клетку; натяжение поверх пинов; пин, проносящийся сквозь жгуты; хвост, протащенный сквозь сетку до перенатяжения на 80%): проникновение в покое 0 px, пересечений в допустимых сценах нет, все сцены засыпают. Прежний solver на тех же сценах оставлял до 22 px проникновения и на перенатянутом жгуте дрожал на 70–100 px за кадр. Сравнение живёт в лаборатории: `demos/collisions.html`.

## Движущиеся пины

Пин несёт позицию из предыдущей сборки индекса (`px`, `py`) и попадает в buckets по всему пути движения за кадр, поэтому быстрый пролёт регистрируется независимо от того, где пин остановился. `querySegmentPins()` схлопывает дубликаты по `order`, так что пин из нескольких buckets возвращается один раз.

Сторону контакта solver берёт из начала кадра с прошлой позицией пина, поэтому пин, проехавший за кадр сквозь отрезок, выталкивает его вперёд по ходу, а не назад.

Во время drag индекс собирается каждый кадр из runtime-позиций, а не из модели, которая обновляется только на pointerup. Карта прошлых позиций (`pinPrevPositions`) живёт отдельно от кэша индекса и переживает `renderUI()`: иначе перерисовка на pointerup стирала бы историю ровно в кадр самого большого скачка пина. Флаг `swept` держит жгуты разбуженными, пока в сцене есть движущиеся пины.

В benchmark на 1000 жгутов число distance checks уменьшилось с 15 984 000 до 124 958, то есть в 127.9 раза. Время зависит от машины и не используется как CI threshold. Benchmark сверяет одинаковое число контактов legacy и spatial paths.

## Взаимодействия

- тело жгута выбирает объект; Alt/Option включает copy drag;
- start и tail handles используют canonical point selection;
- рамка и Cmd/Meta selection записывают те же point keys;
- стрелки двигают выбранные точки на клетку, `Shift` на пять;
- пустой холст отвечает за pan или рамку;
- кисть и ластик обрабатывают клетки между pointer samples;
- grip слоя изменяет порядок.

Обычный body drag отключён. `pointercancel` откатывает незавершённую операцию к снимку перед началом действия.

## Список слоёв и карточка

`renderUI()` перестраивает список целиком, но строку получает только `.item-main`. Карточку настроек и панель действий строит `layerCard(wire, index)` — и только для выбранной строки, поскольку CSS показывает их лишь у `.item.primary`. На 1000 жгутов список занимает 6045 узлов вместо 45006, а `renderUI` укладывается в ~43 мс вместо ~172 мс.

Ту же `layerCard` вызывает `renderCompactCard()` для нижней панели на узких экранах, поэтому мобильный инспектор и десктопная карточка не могут разойтись: контролы и их обработчики создаются одним кодом. Панель показывает карточку выбранного жгута, подсказку без выбора и ничего в режиме кисти.

## Система стилей

Токены живут в `:root` в начале `<style>` в `index.html`. Новые правила берут значения оттуда, а не пишут их заново.

| Токен | Значение | Зачем |
|---|---|---|
| `--font-sans` | IBM Plex Sans (Google Fonts, запасной Arial) | подписи и текст |
| `--font-mono` | IBM Plex Mono (Google Fonts, запасной системный моно) | значения |
| `--type-label` | 11px | подписи и значения |
| `--type-text` | 13px | текст |
| `--tracking` | .06em | разрядка капса |
| `--muted` | .7 | приглушение заголовков и подсказок |
| `--row` | 32px | высота строки в панелях и размер квадратного контрола |
| `--pad` | 6px | внутренний отступ плашек |
| `--gap` | 6px | зазор между плашками |
| `--surface` | фон 72% + размытие | подложка всего, что лежит поверх холста |

Текст бывает четырёх ролей, других нет:

- **подпись** — всё, что называет контрол или раздел: `--font-sans`, `--type-label`, капс, `--tracking`, полная яркость;
- **значение** — то, что можно посчитать или нажать на клавиатуре: цифры, длины, проценты, ID, клавиши. `--font-mono`, `--type-label`, без капса и разрядки;
- **текст** — сообщения, подсказки, описания в шпаргалке: `--font-sans`, `--type-text`, обычный регистр;
- **заголовок панели** — подпись с `opacity: var(--muted)`: «кисть», «жгут 0003 · 13 кл.».

Строка панели — подпись слева, контрол справа, высота `--row`. Контролов четыре вида:

- **полоса выбора** — цвета, фон, вид точек: ячейки в одной рамке, выбранная отмечена двойной чертой снизу;
- **переключатель** — вкл/выкл: дорожка с квадратным бегунком, во включённом состоянии залита;
- **ползунок** — подпись, ползунок и значение моно в одну строку;
- **действие** — квадрат `--row` с иконкой, как «по умолчанию».

Все плашки — тулбары, карточка, панели, шпаргалка — одного вида: рамка 1px, `--surface`, без тени.

## Persistence

| Ключ | Назначение |
|---|---|
| `wires-v2` | модель рисунка |
| `wires-view-v2` | pan и zoom |
| `wires-shapes` | формы жгутов для восстановления после перезагрузки |
| `wires-physics` | гравитация и сопротивление |
| `wires-panels` | какие панели справа открыты |
| `wires-brush-length` | длина кисти |
| `wires-brush-color` | цвет кисти |

`readStorage()` и `writeStorage()` изолируют browser storage errors. При quota failure текущая вкладка продолжает работать, а `.wires` экспорт сериализует актуальный in-memory state.

Undo хранит до десяти JSON-снимков модели в памяти вкладки.

## Доступность

Панели инструментов имеют именованные группы. Toast работает как polite live region. Dialog связан с заголовком и пояснением. Динамические swatches получают accessible names. SVG start/tail handles доступны по Tab, выбираются Enter/Space и двигаются стрелками через тот же constraint path, что pointer drag.

## Оставшаяся граница рефакторинга

Чистая модель, формат и collision solver уже вынесены. Следующие безопасные кандидаты:

- `physics.js` для runtime integration и constraint loop;
- `interactions.js` для pointer/keyboard controllers;
- `ui.js` после стабилизации DOM contracts.

Каждый перенос должен сохранять unit tests, browser smoke и статическую публикацию. Незакрытые вопросы и отложенные идеи — в [бэклоге](BACKLOG.md).
